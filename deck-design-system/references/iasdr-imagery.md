# iasdr 圖像規格：插畫、照片、標誌

適用於 `iasdr` 主題。版型、字級、色票見 `iasdr-typesetting.md`；這份只管**畫面裡的圖像**。

- **依據**：IASDR 2025 研討會簡報的風格觀察，2026-11-06。
- **只描述風格**：素材另外準備，不從原檔抽取任何插畫、照片或標誌。
- **為什麼需要這份**：原版的辨識度有一半來自圖像。範本只有幾何 icon 和空的照片位置時，即使字級、格線都一致，看起來仍然空、像半成品。

## 1. 三種圖像，各有用途

| 種類 | 元件 | 用在 | 不用在 |
|---|---|---|---|
| **插畫** | C63 `.illus` | 卡片的主視覺、說明一個情境（誰、在做什麼、遇到什麼問題） | 清單裡的小標記、表格內 |
| **icon** | C61 `.icon` | 清單、表格、膠囊旁的小標記；抽象概念（書、圖表、介面） | 需要「人」或「情境」的地方 |
| **照片** | C55 `.photo`、`.photo-slot`、C64 `.photo-wash` | 封面、提問頁、結語的背景；內容頁右緣的淡影像；真實產品畫面 | 裝飾用的圖庫照片、和研究無關的人像 |

**選法**：這張卡在講「一個人遇到的情況」就用插畫；在講「一個概念或資料類型」就用 icon。同一頁只用一種主視覺，不要插畫和大 icon 混排。

## 2. 插畫（C63）

### 2.1 線條與顏色

| 項目 | 規格 |
|---|---|
| 線寬 | 在 1920 畫布上 **6px**（插畫高度 200px 左右）；插畫縮到 144px 以下時改 5px。全圖同一線寬 |
| 線頭、轉角 | 圓頭、圓角（`stroke-linecap: round`、`stroke-linejoin: round`） |
| 顏色 | 單色，**由上到下的線性漸層** `--icon-a #0C98FE` → `--icon-b #2F82FC`，漸層以整張插畫的高度計算，不是每條線各自計算 |
| 填色 | 不填色，內部透出卡片的白底。例外：筆尖、按鈕這類 8–16px 的小塊可用實心漸層 |
| 輪廓 | 輪廓刻意留 1–3 處缺口，線條不完全封閉，讓畫面輕一點 |
| 陰影、描邊、灰階 | 都不用 |

### 2.2 造型

- **人物**：簡化的側面半身或全身。頭大、圓，鼻子微微凸出成側臉，沒有五官細節；身體是圓潤的一筆輪廓，手用簡單的弧線。坐姿配椅子，站姿可以只畫到腳。
- **道具**：一到兩件，用圓角矩形組成。常見的有筆電、平板、書、文件、望遠鏡、長條圖，以及右上角帶三個點的瀏覽器視窗。
- **狀態符號**：問號代表疑惑，亂線團代表混亂、資訊過多，虛線箭頭代表移動、成長或思考的方向，小閃光代表發現。一張插畫最多一個狀態符號。
- **人數**：一張插畫一到兩個人。要表達「很多人」時，改用數字磚（C29）或圖表，不畫人群。
- **不要**：寫實人物、膚色、表情、性別或族群的刻板特徵、漸層以外的顏色、3D、扁平色塊插畫。

### 2.3 尺寸與位置

| 用法 | 插畫高度（1920 畫布） | 位置 |
|---|---|---|
| 疊卡（N38a）左側主視覺 | 144–176 | 卡片左欄，垂直置中，與標題同一列開始 |
| 兩欄、三欄卡的上方主視覺 | 160–200 | 卡片內上方置中，下面接標題 |
| 漏斗或流程旁的階段卡 | 144–160 | 卡片上方置中，下面接階段名稱與膠囊 |
| 一頁一張的情境插畫 | 240–320 | 內容區一側，另一側放文字；不超過內容寬的 40% |

- 插畫四周至少留 24px，不要貼邊、不要出血。
- 一組並列的卡片，插畫要同一高度、同一位置，底緣對齊。

### 2.4 檔案

- **格式**：SVG，`viewBox` 從 0 0 開始；線條用 `stroke`，不要把線轉成填色外框，這樣才能統一調整線寬。
- **漸層**：寫成 `<linearGradient id="ig" gradientUnits="userSpaceOnUse" x1="0" y1="0" x2="0" y2="<viewBox 高度>">`。不要用 `objectBoundingBox`：純水平或純垂直的線會整條消失（見 LEARNINGS）。
- **命名與位置**：`assets/illustrations/<人物或情境>-<動作>.svg`，例如 `carer-laptop.svg`、`pharmacist-confused.svg`、`researcher-binoculars.svg`。
- **授權紀錄**：每張插畫在 `assets/illustrations/SOURCES.md` 記一行：檔名、來源（自繪、委託、授權素材的網址）、授權條款。授權不明的不放進來。

### 2.5 準備素材的方式

1. **自繪或委託**：把 2.1–2.3 的規格交給繪者，附上需要的情境清單。這是最接近原版的做法。
2. **找授權素材再改**：選單色線條風格的開放授權插畫，例如 CC0 或允許修改的授權，統一改成 6px 線寬與藍色漸層。造型差太多的不要硬改。
3. **AI 生成初稿再描線**：生成後一定要轉成 SVG 線條重描，統一線寬與漸層；先確認生成工具的條款允許商用與發表。

不論哪種方式，進入範本前都要先比對 2.1 的線寬與漸層。

## 3. 照片

### 3.1 色塊頁的雙色調照片（封面、提問、結語）

- 照片放在 `.photo-slot`，加上 `has-photo` 和 `style="--photo:url(...)"`，涵蓋整頁。
- 處理方式：照片先疊一層 `--field` 色，用色彩增值（multiply）混合，呈現藍色雙色調。照片從畫面中段開始，往左漸漸淡出，左側的文字區保持接近純色。
- 內容：與研究有關的真實場景，例如使用者在工作、在使用系統。人物偏右，視線朝向畫面左側的標題。
- 照片的明暗對比要低，疊色後白字的對比仍要 ≥ 4.5:1（lint R10 會檢查）。

### 3.2 內容頁右緣的淡影像

- 用 `.photo-wash` 加 `style="--photo:url(...)"`，放在投影片的第一個子元素。
- 處理方式：去色、透明度 10%，貼齊頁面右緣，寬度約為頁面的 30%，往左淡出到看不見。
- 一份簡報最多三頁使用，內容要和那一頁的主題相關。內容區的卡片會蓋在它上面，所以不影響閱讀。

### 3.3 頭像與真實畫面

- **講者頭像（C58）**：圓形、無外框，封面上 84px，團隊頁 120–160px。用本人同意使用的照片。
- **產品畫面（C53、C54）**：只放真實截圖，不重畫示意圖（深色頁 L9 的規則）。

## 4. 標誌

- **研討會或計畫的標誌**：封面左上，白色單色，高 48–64px。
- **學校或系所的章**：封面右上，白色單色線條，寬 120–140px。
- 標誌只用主辦方或所屬單位提供的正式檔案。沒有檔案時，**留空**；不要用文字或自己畫的圖形代替。

## 5. 範本裡的佔位

- `.photo-slot` 沒有照片時，只顯示一層淡淡的徑向暗部，模擬照片的位置，**不印出文字**。要在版型庫看到「這裡放照片」的提示，就在 `<body>` 加上 `class="show-slots"`。
- `.illus` 沒有圖時，顯示一個淡色的虛線圓角框，讓作者知道這裡要放插畫。正式簡報不應該留下空框；lint R27（提醒）會列出空的插畫位置。
