# 產品畫面：截圖、影片與授權

原則是只放真的畫面，並且說得出它從哪裡來。模擬介面看起來像產品，卻證明不了任何事；2026-10 的第一版網站放了兩個模擬介面，後來全部拿掉。

## 真實截圖

1. 從公開 Release 下載安裝包，照 README 安裝。不要用開發中的程式，因為介面會不一樣。
2. 用一個拋棄式的 HOME 和全新的空資料夾啟動，不載入研究資料、不呼叫模型。
3. 用瀏覽器截圖 API 拍，記下 viewport 和 device scale（例：1440×820，scale 1.4）。
4. 不修圖。手機版若要放局部，用 CSS 裁同一張圖並標明是局部；不另做一張圖。
5. 填 `assets/provenance.template.json`，和圖片放一起，寫進 sha256。
6. 在原始解析度看一遍：沒有受訪者資料、案例名稱、帳號、金鑰。

## 操作影片

```sh
scripts/encode_web_film.sh input.mp4 site/assets product-film
```

- H.264＋AAC 128k、CRF 23、`+faststart`（不用等整支下載完就能開始播）、拿掉 metadata 與 chapters。60 秒 1080p 約 11 MB。
- 封面取第 2 秒，避開片頭黑畫面。
- `<video controls muted loop playsinline preload="metadata" poster=...>`，寫上 width／height 與 `aria-label`（說明影片長度、有無旁白、內容）。
- 圖說寫：介面版本、案例來源與授權狀態、是否經剪輯、哪些畫面是展示圖層。

## 授權關卡

影片和截圖裡只要出現研究素材（受訪者稱呼、原話、案例或品牌名稱），公開之前：

1. 列出畫面裡出現的每一項，交給負責人看。
2. 取得明確的同意範圍：哪一支影片、哪些人、哪個網站。記在專案紀錄裡。
3. 同意只涵蓋說好的那一項。換一支影片、加一張截圖，都要重新確認。
4. 推送時若被安全檢查擋下，停下來說明原因，等負責人明確說要繼續；不要改用其他方式繞過。

沒有可公開的研究素材時，用空首頁截圖，圖說寫明「沒有研究資料」，不要用虛構案例冒充真實操作。

## 圖表與示意圖

外部做的示意圖（例如人與 AI 分工圖）放上去前，對照網站的 token 色；配色不一致時，先改圖再放，或在待辦記下。
