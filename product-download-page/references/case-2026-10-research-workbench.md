# 案例：研究工作台下載頁（2026-10）

這個 skill 的來源案例：一個 AI 輔助的服務設計研究工作台（Mac 預覽版），網站在 GitHub Pages，下載指向 GitHub Release。

## 經過

| 日期 | 事件 |
|---|---|
| 10-20 | 第一版：拿掉兩個模擬介面（五分頁概念工作台、虛構的編輯確認練習），改放開發版空首頁截圖；token 由產品 design system yaml 產生 |
| 10-21 | 0.2.0 發佈；Pages 上線；截圖改從安裝好的 0.2.0 重拍（舊圖是開發中的舊介面）；一段流程描述還寫舊方法，改寫；加入人與 AI 分工圖（點擊放大） |
| 10-22 | 首頁截圖換成 60 秒操作影片。影片有受訪者稱呼與原話，負責人明確表示已取得同意後才上；推送時被安全檢查擋下，負責人說繼續後才推 |
| 10-24～25 | 發了兩個新版本；下載按鈕自動指到新版，網站其他內容沒更新 |

## 學到的事

- 網站跟著產品版本走，但只有一部分會自動跟上。連 `releases/latest` 的按鈕會；截圖、圖說版本號、流程描述不會。發版清單要把它們列進去。
- 截圖要從安裝好的發行版拍，不是從開發環境拍。來源紀錄寫 sha256，加上渲染它的 UI 檔 sha256，之後 UI 改了查得出來。
- 本機預覽開到過期副本：主工作樹裡有一份未追蹤的舊網站，本機伺服器開的是它。之後只留分支 worktree 一份。
- 驗證要打線上網址：頁面標記、影片分段請求 206、封面 200、`releases/latest` 指到哪個 tag。用 GET 帶 Range，不要用 HEAD，有些主機對 HEAD 加 Range 回 200。
- 外部示意圖的配色（深色加紅藍）和網站 token 不一致，放上去之後才發現；應該放之前先對照。
- 沒有可公開的研究素材時，空首頁截圖是誠實的選擇；曾考慮的主要操作畫面輪播，因為缺可公開的資料而沒做，後來被操作影片取代。
